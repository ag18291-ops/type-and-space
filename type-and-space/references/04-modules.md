# 04 — Modules

Tags: **CORE** established rule · **EST** estimated · **ADAPTED** translated for modern UI/marketing.

## Reference text module

**Heading covers text.** Everything else is a mutation of this. Canonical vertical order: **image → caption → heading → text → links** (CORE; the version with the image at the bottom is wrong). CORE

- Keep it rectangular. Avoid very long, narrow vertical text columns on screen. CORE
- Continuation links go at the end. One link: merge it with the heading **only if sibling modules do the same** (uniformity), and then make the image clickable too. CORE
- A lone important link gains weight by a tag above, a caption below, bold, or a tinted plate. CORE
- Do not break heading from the start of text. Send minor links, captions, tags and controls to the end: ad example, description right after the headline, then the label/domain/phone row last. CORE
- Complex block: reduce size and weight, and increase detail, from top to bottom (or left to right across columns). Small attaches to large. CORE
- Mutations: subheads dividing vertically; columns dividing horizontally; heading hanging in one column. A hanging heading is "Swiss" on a simple airy page (NASA manual) but the text then has no separation from the block above: add a rule or space. CORE
- Heterogeneous elements may sit in columns too (a form: labels column, fields column). CORE

## Feed

A list of news headlines, links, rubrics or comments. CORE

- Tag **above** the link (category, date); caption **below** it (description, counts). Dates work as tags only for live feeds; otherwise put the date in the headline. In compact one-line widgets drop captions. CORE, EST
- Many rows: separate by distance (extra ≈ 0.5 line between multi-line items) and sometimes by rules; a rule sits closer to the item that follows it (≈ 1.3–1.6 : 1). Rules turn a dangerous layout into an acceptable one, not an ideal one. EST
- A hanging tag column is **accepted when rules separate the items** and rejected when items run together with leading only. Check neighbours above and below. CORE
- Narrow vertical feeds fit the screen height where possible; exception: a side rail of "interest generators" (USA Today) that is not studied. CORE
- A thumbnail beside the heading is allowed in a narrow side feed. CORE
- Short feeds may spread into columns or a horizontal band. Columns equal in height, or at least each next column no longer than the previous: fix item count, limit headline length, or compute height. CORE
- Larger structure: subheads. Columns may contrast in link styling; reduce size and increase detail left to right. CORE
- Social feeds: an endless middle column (≈ 45 % of the window) with fixed side columns; item gap ≈ 2.4 pitch in the schematic. EST

## Text with illustration

- Illustration is best at the top of a vertical block. Under the heading it interrupts reading; at the bottom it makes the block heavy and two-poled and may attach to the block below: **questionable, not forbidden**, and it can work in a calm uncluttered design. CORE
- Ideal: illustration width = text width; cut-outs align left or centre and compensate optically for shape and ragged right. CORE
- **Horizontal module:** image left or right by gaze: the look or action points at the text. Proportions: image ≈ 37 % of module width, gap ≈ 5 %, text ≈ 46 %; image top on the heading top, image bottom on the last text line. CORE, EST
- Screen risks: text from a database has unpredictable height and images fixed height, which leaves holes. Crop the thumbnail to the height of the text part, or limit headline lines, or use equal typed thumbnails. CORE
- **Armpit:** a heading that spans the full width **above** an image and its text puts the image "under its arm" and separates the heading from the start of the text. Only the **right** armpit is acceptable (text under the heading on the left, image on the right). A heading stacked with an image in a narrow left column is the same defect. CORE
- **Not an armpit:** a small image (userpic, thumbnail) at the top-left of a module whose text column carries its own heading. Keep it top-aligned and sized to the text part; do not leave a dead column below it. CORE
- **Text wrap:** never wrap text beside an image that stands at the **left** of a module (the left edge jumps to a random place and the eye catches it as a start of text). The fix is to put the image on the right. CORE
- Stacked side-image modules fuse their images into one column and the text reads independently. Draw the rule across image **and** text so each module is bound, and expect a pitch ≈ 1.3–1.5 × larger. CORE, EST
- **Text over image:** beautiful if the image agrees with the text, otherwise unreadable. Two techniques: choose or compose an image with a calm flat zone reserved for the text; or use a scrim or gradient. CORE
- Several images in one module keep the rectangle: a row with matched heights; a matrix of typed thumbnails (gutters ≈ 1–3 % for photo grids); a collage; or typed images flowed like text. Many tiny images are hard to examine: make a **photorama** (one ideal image with a switcher of thumbnails) in a vertical or horizontal module. CORE, EST

## Dominant and supporting images

- Equal images quarrel; one dominates and says "start here". The sequence: six equal = so-so; one dominant + six equal small = better; dominant + medium + two small = good. The supporting images should differ among themselves too; the dominant is ≈ 2.4 × the supporting width in the examples. CORE, EST
- Options: row above text (calm, wide, needs full width: home pages); stack beside text (unusual; hard to keep dominance); **dominant on top + supporting beside text** (home pages); dominant beside + supporting above (needs very short text). CORE (–5: one big + two small, or big left + two small stacked right, both pass; three equal images with equal links fails)
- **Two or more images stacked above text** form a heavy brick too far from the text: anti-pattern. CORE
- A supporting image may sit left or right; a portrait looks toward the text. Shrunk to a userpic it works in social feeds; a tiny hanging avatar that wastes a column does not. CORE
- A supporting image never competes with the main one. Vertical images: block above text works; a heavy vertical brick beside text does not; a small vertical beside text works as a portrait; a vertical dominant may take the height of two horizontals; a second tier of different sizes keeps hierarchy. Do not crop verticals to squares by default. CORE
- All examples hold for squares. Any rectangular object can take the supporting slot: form, plate with a buy button, diagram, chart, map. CORE

## Reading order

- Left→right, top→bottom. A column broken by an image makes the eye search; broken by a banner it may look finished. CORE
- After a column the eye goes to the **top** of the next. Align columns at the top. Heights equal in print; on screen each next column no longer than the previous and the difference not excessive. Unlinked columns may break the rule. CORE
- Matrix of text blocks: order unclear; safe only if order does not matter. Bring related blocks closer, number them, add rules, or break the alignment of a row to force columns. CORE
- Two long link lists side by side: headings scroll away; stack them vertically (the better version). CORE
- The position of the illustration sets the direction; use the same vertical order across columns (image on top, text below) so the gaze path stays one simple line. A Z path (left to right, down, left to right) is the reading of a one-column text. CORE
- Related elements aligned by width and height visually unite; **accidental alignment creates a pseudo-module** (see C2). CORE
- A comment block must stay next to its article, not behind another module of news. CORE

### Modular rules
1. A module is a rectangle or is formed by empty space.
2. Internal elements agree with the reading direction.
3. Aligning width, height or position creates a module (or pseudo-module).
4. Modules do not intersect or intrude.
5. Neighbouring modules must not mislead the reader.
